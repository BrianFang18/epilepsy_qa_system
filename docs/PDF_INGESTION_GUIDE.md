# PDF 文档入库指南

> [!WARNING]
> **状态：操作草案，尚未在本轮复核。** 本指南不保证旧版 `scripts/pdf_ingest.py`、`crawl_and_ingest.py`、目录布局或命令仍受支持。旧命令仅保留为历史线索，执行前必须根据当前代码和 `--help` 单独核对。本文不提供解析质量、检索提升或临床效果的预期数值。

## 背景：PDF 全文可能补充什么？

PubMed 摘要与指南、药品说明书全文的内容范围不同。依法取得并正确解析的全文**可能**补充分类定义、适应症、禁忌、剂量、急救流程等细节，但是否改善覆盖取决于文档许可、版本、解析准确性、分块、索引和具体评估集。

| 内容类型 | 摘要中可能的覆盖 | 全文中可能的补充 | 入库前需核对 |
|---|---|---|---|
| 分类与定义 | 可能仅有概述 | 定义、分层和限定条件 | 来源、版本、适用人群 |
| 药品信息 | 可能不完整 | 适应症、禁忌和警示 | 监管地区、修订日期 |
| 临床指南 | 可能只有结论摘要 | 推荐等级和完整流程 | 发布机构、版本、许可 |
| 剂量与规格 | 常非摘要重点 | 规格、给药与特殊人群说明 | 原文完整性、表格解析 |
| 急救流程 | 可能只有研究结论 | 流程、阈值与例外 | 时效性和适用场景 |

PDF 入库本身不能“从根本上解决” retrieval 覆盖，也不能证明回答质量、临床安全或临床效果。

## 1. 来源、许可与安全前置条件

1. 只处理有合法访问权和允许用途的文档，记录来源 URL、许可、版本和下载日期。
2. 医学指南和药品说明书会更新；索引时保留发布机构、适用地区、发布日期与替代版本关系。
3. 不将患者病历、身份信息或其他敏感正文混入公开评估或示例。
4. PDF、OCR 输出和外部文本均按不可信输入处理；解析或展示时防止路径穿越、脚本内容和异常超大文件。
5. 入库前建立备份、回滚与去重策略，不直接覆盖现有知识库。

---

## 2. 解析依赖（环境相关）

历史草案曾使用 PyMuPDF、pdfplumber、Tesseract、Pillow 等组件。具体依赖和版本应以当前项目锁定配置为准，不要仅依据本文执行无版本上限的安装命令。

需要 OCR 时，还应记录：

- OCR 引擎与语言包版本；
- 页面是否为扫描图、是否旋转或模糊；
- 哪些页面进入 OCR fallback；
- 解析失败、空页和低置信度页数量。

## 3. 文档组织建议

以下目录仅为组织示例，不代表当前脚本已验证支持：

```text
<approved-pdf-root>/
├── guidelines/      # 指南或共识
├── drug_labels/     # 经核准的药品说明书
├── textbooks/       # 有相应使用许可的教材内容
└── protocols/       # 诊疗规范
```

文件名建议稳定、可追踪，元数据中另存原始标题、文档版本和校验摘要。不要仅根据目录名自动断定 `doc_type`；应由人工或可审计规则确认。

## 4. 历史入库命令的状态

旧版指南曾将以下名称描述为“一条命令完成”或批量重建流程：

- `scripts/pdf_ingest.py`
- `scripts/crawl_and_ingest.py`
- `extract-only` / `ingest-only`
- 自动按目录推断 `doc_type`
- 自动追加到 JSON 后清空并重建旧索引

这些名称和行为在本指南中均标记为 **historical unsupported / 未复核**。在恢复任何流程前，至少应确认：

1. 当前脚本存在且参数与 `--help` 一致；
2. 输入和输出目录受限，且不会读取未授权文件；
3. 解析预览经过人工检查；
4. 文档 ID、版本和幂等策略明确；
5. 写入目标为隔离的 staging collection；
6. 核数、激活和回滚步骤可审计；
7. 任何“清空旧数据”或覆盖动作均另行备份并由人工确认。

> **破坏性操作警告**：批量清空、覆盖、合并或重建知识库可能造成不可逆的数据丢失或版本混杂。本指南不授权执行此类操作。

## 5. 解析质量验收

不要为不同 PDF 类型预设星级或声称“与原文一致”。对每份文档保存可复核结果：

| 检查项 | 记录方式 |
|---|---|
| 页数完整性 | 原文件页数、成功页、空页、失败页 |
| 文本完整性 | 抽样页逐段比对；记录缺段、乱码和顺序错误 |
| OCR | 有标注时计算字符/词错误；无标注时记录人工抽检范围 |
| 标题与层级 | 检查章节顺序、列表和脚注归属 |
| 表格 | 检查表头、行列、单位和合并单元格是否保留 |
| 关键数字 | 人工核对剂量、时间阈值、百分比和单位 |
| 元数据 | 核对来源、版本、日期、许可和校验摘要 |
| 失败处理 | 失败页不静默跳过，进入隔离队列并阻止激活 |

解析质量通过也只说明文本转换达到所定义的门槛，不能自动推出检索或临床质量。

## 6. 入库与检索验证

建议按以下顺序验证，不预设结果方向：

1. 在隔离环境中解析并生成预览；
2. 人工核对代表性页面和高风险字段；
3. 分块后检查标题、页码、来源与 chunk 的可追溯关系；
4. 写入 staging 索引并核对文档/chunk 数；
5. 使用预先定义且独立于待测文档构建过程的查询集检查召回；
6. 保存失败查询与误召回，再决定是否激活；
7. 激活后保留回滚到上一索引版本的能力。

不能仅通过查看一条生成答案就宣称 PDF 已正确入库或 retrieval 已提升。

## 7. 当前评估边界

`POST /v1/eval/ragas` **仅是 legacy compatibility URL**；当前未安装、也未运行 Ragas。实际口径是：

- `backend=deterministic_lexical`
- `metric_version=token_overlap_v1`
- `aggregation=macro_average`
- `context_precision`：ground truth 与 retrieved contexts 的 context-hit ratio（兼容字段）
- `context_recall`：ground-truth token coverage（兼容字段）
- `response`：不参与计算

因此，该 endpoint 最多用于比较 ground truth 与 retrieved contexts 的确定性词项重叠。它不代表 Ragas、faithfulness、答案事实正确性、临床安全或临床效果。

public-eval 与这个 legacy endpoint 是不同 contract：public-eval 的 dry-run 只校验公开 synthetic 数据和输出结构，不发 HTTP；live run 也只能按其预先定义的公开指标解释。两者均不能因 URL 或字段名称而改称为 Ragas。

本指南不再提供私有答案文件、benchmark、`eval_with_answers.json` 或其他私有评估输入的运行示例，也不提供“入库后指标应显著提升”或任何预期区间。

## 9. 故障处理原则

- **依赖缺失**：根据当前锁定环境修复，不使用本文猜测版本。
- **乱码或 OCR 失败**：隔离失败页，记录原因，不静默入库。
- **表格结构损坏**：高风险表格在人工核对前不得激活。
- **服务不可达**：保留 staging 输入和日志，恢复服务后幂等重试。
- **结果异常**：先核查数据来源、解析、分块和指标定义，不把单一 lexical 数值解释为回答或临床质量。
